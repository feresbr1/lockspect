# Contributing to lockspect

Thanks for helping. The most useful contribution of all is a bug report with a lockfile that parses wrongly.

## Reporting a parsing bug

Open an issue with the package manager and its version (`npm -v`, `pnpm -v`, …) and a **minimal** lockfile that shows the problem. Remove private package names first. A lockfile generated from a three-line `package.json` is perfect.

## Development setup

Requires Node.js 22 (the CLI itself supports Node 18.17+).

```sh
npm install
npm run dev          # http://localhost:5173/lockspect/
npm test             # vitest, network mocked
LIVE=1 npm test      # also runs the live OSV.dev / deps.dev / npm checks
npx playwright install chromium
npm run build:web && npm run test:e2e   # serves dist/web, desktop + mobile
npm run check        # everything CI runs except e2e
```

## Project layout

```
src/core/          lockfile parsers, data sources, report building (no DOM or Node APIs)
src/core/parsers/  one file per lockfile format
src/web/           Preact UI
src/cli/           command line entry point
dist/cli/          committed CLI bundle used by `npx github:` and the GitHub Action
test/fixtures/     real lockfiles generated by each package manager
examples/          demo lockfiles used by the website samples
e2e/               Playwright tests
```

## Guidelines

- **Fixtures must be real.** Generate lockfile fixtures with the actual package manager (`npm install --package-lock-only`, `pnpm install --lockfile-only`, …) instead of writing them by hand.
- **Keep `src/core` portable.** It runs in the browser and in Node. Pass `fetch` in, and never import `node:*`.
- **Never send more than names and versions** to a third-party API.
- **Rebuild the CLI bundle** (`npm run build:cli`) and commit `dist/cli/lockspect.mjs` whenever you change code it includes. CI checks this.
- Run `npm run check` before opening a pull request.

## Releasing

1. Update `version` in `package.json` and `src/core/version.ts`, and add a `CHANGELOG.md` entry.
2. Run `npm run build`, then commit.
3. Tag `vX.Y.Z`, move the major tag (`git tag -f v1 && git push -f origin v1`), and publish a GitHub release with `dist/cli/lockspect.mjs` attached.
